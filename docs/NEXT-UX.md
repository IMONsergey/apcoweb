# Next UX candidates — not implemented in R3

These are optional improvements, not new product commitments. R3 only implements the requested contextual billing panel and the verified usability repairs.

## 1. Share the selected plan and billing period

A link such as `?billing=annually#plan-business` could reopen the same comparison state after refresh or when shared with a colleague. Limit the stored state to this landing page; do not invent checkout parameters for the existing product. This is the most useful next increment because it extends the billing dock without adding another visible control.

## 2. Keep comparison labels visible on narrow screens

In the existing plan-comparison dialog, retain the first column while the visitor scrolls horizontally, and use edge shadows only when there is hidden content. This clarifies which feature a number belongs to. It should not add a second floating global panel.

## 3. Offer validated query examples after search focus

A small optional row could insert a real example into the search field without automatically submitting it. Supported syntax and credit implications must come from the product team. Do not invent filters or claim that a query is free beyond the already approved public-search copy.

## Avoid

No timed sales popup, fake scarcity/countdowns, scrolling interception, forced auto-open FAQ, global motion toolbar or extra sticky CTA covering the current panel. A contextual control should solve the task in view, not compete with it.
